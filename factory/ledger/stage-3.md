## Readings chosen where the specification is silent or ambiguous

1. **Instants**: `as_of`, `known_at`, `from`, `to` (and a correction's `effective_at`) must be RFC 3339 with an offset
   (`Z` or `±hh:mm`, fractions allowed); naive times, bare dates, empty values and junk are 422 `validation_failed` for
   all four query parameters. Equality is by instant; the *echo* of `as_of`/`known_at` is compared as the exact string.
2. **Default `to` is now** and a payment made at the same instant as the read is not asserted either way; probes never rely on it.
3. **Correction permission order**: unknown payment 404; any authenticated non-sender (receiver or stranger) 403, also for
   settlement members and captures; the sender of a member/capture gets 422 `linked_payment_immutable`; then field
   validation 422; then `stale_revision` 409; then `insufficient_funds`; then `historical_overdraft`. Only the pairs
   stated in the spec (insufficient before historical; claimed idempotency key before validation) are asserted.
4. **Wrong JSON types** in a correction body (string revision, numeric reason …): 400 `malformed_request` or 422; amount
   string/boolean/fraction is 422 (stage-1 §5 rule); `amount` 0 and 1000000000 are valid, 1000000001 and −1 are not.
5. **`effective_at` may be any instant not later than now**, including before the payment's own `created_at`; an
   unchanged amount with a new effective time is a legal correction (difference 0, no current debit).
6. **Revision list items** carry `payment_id`, `revision`, `amount`, `effective_at`, `recorded_at`, `reason` (compared as instants).
7. **`closed_at`** is present (null) on every authorization representation; for a clock expiry it equals `expires_at`; for
   a final/full capture it equals the capture payment's `created_at` (±1 s tolerated); for a void it is the void time.
8. **Hold views**: a hold exists from its creation instant (inclusive); a nonfinal capture reduces it at the capture
   payment's time; final capture/void release the remainder at their event time; an event is known from its event time;
   expiry at `expires_at` (inclusive) and the deadline is known as soon as creation is; therefore as of a time after the
   deadline an open-in-this-view hold is released whatever `known_at` is, while a void/capture later than `known_at` is unknown.
9. **Historical overdraft boundaries**: every effective time of the latest known revisions plus every hold event
   (creation, nonfinal capture, release, expiry) up to now; at each, `total ≥ 0` and `available ≥ 0` with all movements
   at the same instant combined.
10. **Timestamp resolution**: probes separate causally ordered events by 1.1–1.3 s and probe instants at ±0.4 s, so they are
    valid for whole-second and finer clocks; recorded times of back-to-back corrections must still strictly increase.
11. **Snapshots**: snapshot pages need not repeat the `snapshot` key; survival across import is not asserted; `as_of`
    (not a statement parameter) is ignored like any unknown parameter, also together with a snapshot.
12. **`GET /me` without temporal parameters** may carry extra keys; only the money fields are asserted.
13. **Expiry probes need wall-clock time** (a 4 s TTL and one ~6 s sleep; hold-lifecycle probe sleeps ~7 s in total).

## Running the probes

    python3 factory/probes/stage-3/run_all.py http://127.0.0.1:8080                      # stage-3 + stage-1/2 non-UI regression
    python3 factory/probes/stage-3/run_all.py http://127.0.0.1:8080 --no-prior            # stage-3 probes only
    python3 factory/probes/stage-3/run_all.py http://127.0.0.1:8080 --stage1-url http://127.0.0.1:8081 --stage2-url http://127.0.0.1:8082
    python3 factory/probes/stage-3/run_all.py http://127.0.0.1:8080 --with-ui --peer http://127.0.0.1:8083
    python3 factory/probes/stage-3/check_ledger.py                                         # ledger <-> probe cross-check (no service)

Python 3.8+ standard library; `--with-ui` needs Playwright + Chromium (otherwise those probes report SKIP).
`--stage1-url` / `--stage2-url` are running stage-1 / stage-2 services of the same team whose exports are imported
into the service under test (without them the two import probes report SKIP, not PASS). Probes wipe all service state;
use a disposable container. Exit status 0 only if nothing fails.
