## Readings chosen where the specification is silent or ambiguous

1. **Capture after clock expiry**: `authorization_expired` when `expires_at <= now` (the status is `expired` by the
   clock); `authorization_not_open` for `captured`/`voided`; `void` on an expired one is `authorization_not_open`
   (explicit in the spec).
2. **Check order for capture/void**: unknown → 404; not the permitted party → 403 (even on a closed authorization);
   then state (409); then amount (422 `capture_exceeds_authorization` / `validation_failed`). Capture amount
   errors: `0`, negative, fractions, strings, booleans → 422 `validation_failed` (stage-1 §5 amount rule).
3. **`final` wrong type** (`"false"`, `0`, `1`, `null`): 400 or 422, never applied.
4. **`payment_ids` / `remaining_amount`** are present on every authorization representation (create, list, void),
   `payment_ids == []` and `payment_id == null` before any capture; seeded closed authorizations show
   `remaining_amount: 0`.
5. **Idempotency body equality** stays "same JSON value": `{"amount": 700}` vs `{"amount": 700, "final": true}` conflict.
6. **`authorization_ttl_seconds` invalid** (0, negative, fractional, string, boolean, array, object): reset error, state
   unchanged — 422 for numbers, 422 or 400 for wrong JSON types. `null` is not asserted.
7. **Seeded `captured` authorizations**: only their `status`, `remaining_amount: 0` and absence of a hold are asserted
   (the fixture carries no `captured_amount`); the UI shows `authorization-captured-{id}` equal to whatever
   `captured_amount` the API reports.
8. **Where the authorise form lives** is not specified: probes accept `authorize-*` on `/authorizations` or on `/`.
9. **Browser conventions**: signed-in state is persisted by the browser (storage/cookie) across navigations; unauthenticated
   visits to a screen may redirect to `/login`; `Accept: text/html` on a route returns HTML (or a redirect) without a bearer token.
10. **Refresh races** (S2-075) are exercised by delaying `GET /me` and `GET /activity` in the browser; if a UI refreshes by
    full navigation instead of fetch, no out-of-order read can be staged and the probe degrades to checking the refreshed values.
11. **Text matching**: "text is exactly" compares `textContent` trimmed of surrounding whitespace, with a single ASCII space
    between amount and currency code.
12. **Quality heuristics** (S2-010…S2-019) are objective proxies: no horizontal scroll at 375 px and 1280 px, `<label>` for
    every visible input, a focus indicator on every tab stop, WCAG AA contrast of visible text, links between the four main
    screens in a consistent order, no raw ids / ISO timestamps / minor units in feed and authorization items, human status
    words and ≥3 distinct style signatures across request and authorization statuses, `wallet-available` larger than
    `wallet-balance` and `wallet-held`. Screenshots of every screen at both widths are written to `$PF_SHOTS`
    (default `/tmp/pocketful-stage2-shots`) for the reviewer's visual judgement; those rows are marked manual.
13. **Expiry probes need wall-clock time** (3–4 s TTLs, one sleep of ~6 s; the import-deadline probe sleeps ~5.5 s).

## Running the probes

    python3 factory/probes/stage-2/run_all.py http://127.0.0.1:8080                       # stage-2 + stage-1 regression + browser
    python3 factory/probes/stage-2/run_all.py http://127.0.0.1:8080 --no-ui                # API only
    python3 factory/probes/stage-2/run_all.py http://127.0.0.1:8080 --peer http://127.0.0.1:8081 --stage1-url http://127.0.0.1:8082
    python3 factory/probes/stage-2/check_ledger.py                                          # ledger <-> probe cross-check (no service)

Needs Python 3.8+; the browser probes need `pip install playwright && playwright install chromium` (they report SKIP,
not PASS, when it is missing). `--peer` = a second stage-2 container (cross-instance import); `--stage1-url` = a running
stage-1 service of the same team whose export is imported (or `--stage1-export FILE`). Probes wipe all service state;
use a disposable container. Exit status 0 only if nothing fails.
